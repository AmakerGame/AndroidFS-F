## Обзор

AndroidFS-F — форк [AndroidFS](https://github.com/Lauriethefish/AndroidFS). На телефоне запускается небольшой демон, а хранилище телефона передаётся в Windows через драйвер файловой системы [Dokan](https://dokan-dev.github.io/). Телефон появляется в Проводнике с собственной буквой диска и работает с любой программой.

Этот форк добавляет приложение с окном, списком устройств и управлением, поддержку 32-битных ARM-телефонов и Windows 7, а также ряд исправлений стабильности.

## Возможности

- **Приложение с окном.** Список подключённых устройств, их состояние и кнопки **Mount**, **Unmount**, **Open**.
- **Автоматическое монтирование.** Подключили телефон — появился диск; отключили — диск корректно убирается.
- **Поддержка `arm64-v8a` и `armeabi-v7a`.** Нужный демон выбирается по процессору телефона.
- **Полный доступ на чтение и запись.** Создание, копирование, переименование, перемещение и удаление файлов и папок. Ошибка записи (например, переполненный диск) возвращается в Windows, а диск не отваливается.
- **Журнал** в окне и в файле.
- **Автозапуск с Windows** в свёрнутом виде.
- **Один установщик**, который ставит и Dokan.

## Требования

| Компонент | Требование |
|-----------|------------|
| Windows | 7 SP1 или новее, 64-разрядная (для Dokan на Windows 7 нужно обновление подписей SHA-2) |
| Драйвер | [Dokan 1.5.x](https://github.com/dokan-dev/dokany/releases/tag/v1.5.1.1000) (ставит установщик) |
| ADB | `adb.exe` из [platform-tools](https://developer.android.com/tools/releases/platform-tools) в `PATH` или указанный в настройках |
| Телефон | Android с включённой **отладкой по USB**, `arm64-v8a` или `armeabi-v7a` |
| Графика | Видеодрайвер с OpenGL 2.0 (нужен для окна) |

## Установка

1. Скачайте `androidfs_f_installer.exe` из последнего успешного запуска на странице [Actions](https://github.com/AmakerGame/AndroidFS-F/actions) (артефакт **installer**).
2. Запустите установщик, при желании включите автозапуск. Если попросит, перезагрузите Windows, чтобы загрузился драйвер Dokan.
3. Убедитесь, что `adb.exe` доступен.

Переносимая версия `androidfs_driver.exe` лежит в артефакте **standalone**, но Dokan нужен и для неё.

## Использование

1. На телефоне: *Настройки > О телефоне*, семь раз коснитесь *Номер сборки*, затем в *Параметрах разработчика* включите *Отладку по USB*.
2. Подключите телефон кабелем и разрешите компьютер на экране телефона.
3. Запустите **AndroidFS-F**. Телефон появится на вкладке **Devices** и смонтируется на первую свободную букву, начиная с `Q:`.
4. **Open** открывает диск в Проводнике, **Unmount** безопасно размонтирует его перед отключением.

Закрытие окна размонтирует все диски и завершит приложение.

## Настройки

Вкладка **Settings**, файл `%APPDATA%\AndroidFS-F\settings.ini`.

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| Mount automatically | Монтировать устройства сразу после обнаружения | Включено |
| Start with Windows | Запуск свёрнутым при входе | Выключено |
| ADB path | Полный путь к `adb.exe` | Автопоиск |
| Drive root | Каталог Android, показываемый как диск | `/storage/emulated/0` |

Для автопоиска `adb.exe` проверяются `ANDROIDFS_ADB`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `%LOCALAPPDATA%\Android\Sdk\platform-tools` и `PATH`.

Параметр командной строки `--background` запускает приложение свёрнутым.

## Телефоны с root и без root

Настройки > *Доступ на телефоне*:

| Режим | Поведение |
|-------|-----------|
| Автоматически (по умолчанию) | Запуск от пользователя ADB `shell`. Если он не может прочитать выбранную папку, а телефон с root, демон автоматически перезапускается через `su`. |
| Без root | `su` не используется. Работает на любом телефоне, но только в рамках прав `shell`. |
| Root (su) | Всегда через `su` (Magisk, SuperSU, KernelSU, `su 0`, `su root`, а также если adbd уже работает от root). Нужен для `/data`. Подтвердите запрос на телефоне. |

У каждого устройства на вкладке **Devices** свой раздел *Access for this device* (режим и папка), он хранится по серийному номеру и перекрывает глобальные настройки. С root и без выбранной папки показывается всё устройство (`/`), а не только общее хранилище. В списке устройств видны режим доступа и смонтированная папка. Кнопки рядом с *Drive root* быстро выбирают общее хранилище, `/`, `/storage` или `/data`.

## Дополнительные возможности

- **Сетевые устройства:** введите `ip` или `ip:port` в поле *Network device* и нажмите Connect (`adb connect`). Адреса запоминаются и подключаются автоматически; *Forget* удаляет адрес.
- **Режим только чтения:** по умолчанию в Settings или отдельно для устройства. Windows тогда не может записывать, переименовывать и удалять файлы на телефоне.
- **Сохранение дат файлов** при копировании на телефон (изменения и доступа), поэтому фото сохраняют порядок в галерее.
- **Подсказки** для устройств, которые видит adb, но которые ещё нельзя использовать (*unauthorized*, *offline*).
- **Паузы между повторами:** неудачное монтирование повторяется через 15 с, 30 с, 1 мин ... до 5 мин.
- **Стабильные буквы дисков:** каждое устройство сохраняет свою букву между запусками; другую можно выбрать для устройства (*Access for this device*).
- **SD-карта / USB-диск как корень** (кнопка `SD / USB`, значение `@external`): первое съёмное хранилище в `/storage`, удобно для TV-приставок.
- **Open adb shell** одним кликом и **Copy diagnostics** на вкладке Log для отчётов об ошибках.
- Журнал обнуляется на 2 МБ, а недоступные сохранённые сетевые адреса переподключаются в фоне без задержки монтирования.
- Кнопка **Remount**: применяет изменённые режим доступа, папку, букву или «только чтение» без переподключения устройства.
- **Проводник больше не зависает:** запрос, на который телефон не отвечает 90 с, завершается ошибкой, а потеря связи обнаруживается сразу.
- **Настройки диска** (Settings > *Disk*, большинство можно менять отдельно для устройства): имя диска, скрытие файлов с точкой (атрибут «скрытый»), показ как съёмного диска (Eject), открытие Проводника после монтирования, интервал обновления папок (1-120 с), буква и режим «только чтение».
- **Правильное свободное место**, когда корень диска `/` или `/storage`: Windows больше не отказывает в копировании из-за «полной» корневой ФС.

## Сборка

Нужны: nightly Rust с `rust-src` (приложение собирается под `x86_64-win7-windows-msvc`, поэтому работает и на Windows 7), [cargo-ndk](https://github.com/bbqsrc/cargo-ndk), Android NDK (переменная `ANDROID_NDK_HOME`), Dokan 1.5.x с файлами для разработки и Windows SDK.

```powershell
rustup toolchain install nightly --component rust-src
rustup +nightly target add aarch64-linux-android armv7-linux-androideabi
cargo install cargo-ndk
./build.ps1
```

Сначала собираются демоны для двух архитектур, затем приложение Windows, которое встраивает их через `include_bytes!`. Результат: `target/x86_64-win7-windows-msvc/release/androidfs_driver.exe`. Логику демона и протокол можно проверить без телефона командой `cargo test --lib`.

## Устранение проблем

| Симптом | Решение |
|---------|---------|
| «ADB is not available» | Установите platform-tools и добавьте `adb.exe` в `PATH` или укажите путь в Settings |
| Телефон не в списке | Включите отладку по USB, переподключите кабель, подтвердите ключ на телефоне |
| Статус *Failed* с сообщением Dokan | Установите Dokan 1.5.x и перезагрузите Windows |
| Окно не открывается | Обновите видеодрайвер: нужен OpenGL 2.0 |
| «Already running» | Приложение уже запущено, найдите его на панели задач |

Подробности: вкладка **Log** или `%APPDATA%\AndroidFS-F\androidfs.log`.

## Ограничения

- Скорость ограничена отладкой по USB, а права доступа — это права пользователя `shell`.
- Поддерживаются только `arm64-v8a` и `armeabi-v7a`.
- Дескрипторы безопасности файлов и альтернативные потоки не поддерживаются.

## Что изменено в этом форке

- Приложение с окном: список устройств, действия Mount / Unmount / Open, настройки и журнал.
- Поддержка 32-битных ARM-телефонов (`armeabi-v7a`) наряду с `arm64-v8a`.
- Приложение для Windows собирается так, чтобы работать на Windows 7 SP1 и новее.
- Иконка приложения, выбор автозапуска и ярлыка в установщике.
- В демоне реализованы создание файлов и папок, запись, усечение и безопасное удаление.
- Ошибки записи (например, переполненный диск) возвращаются в Windows, а диск не отваливается.
- Исправлен сбой при чтении за концом файла и неверные коды ошибок для отсутствующих файлов.
- Корень диска — общее хранилище телефона; ошибки ADB больше не останавливают приложение.
- Символические ссылки на каталоги показываются как каталоги.
